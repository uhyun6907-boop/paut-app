# PAUT 오늘 작업

현장 검사자가 휴대폰에서 위상배열초음파(PAUT) 포인트(합격/불합격)를 입력하면, 같은 내용이 개인 OneDrive에 있는 엑셀 세 권에 반영됩니다. PC의 데스크톱 Excel은 OneDrive 클라이언트로 그 파일을 그대로 엽니다.

데모 모드에서는 로그인 없이 이 저장소에 포함된 통합 문서만으로 같은 흐름을 쓸 수 있습니다.

포함된 샘플:

| 파일 | 내용 |
| --- | --- |
| `public/samples/ndt-list.xlsx` | 비파괴검사 리스트. 현장마다 시트. 헤더 4행, 데이터 6행부터 |
| `public/samples/work-log.xlsx` | 작업일지 `PAUT FIELD` |
| `public/samples/statement.xlsx` | 월별 거래명세서 |

`택지 드림 RT` 시트는 방사선 검사라 읽지 않습니다.

**지운 현장.** `지성 브레인`, `택지 드림`(드림 택지)은 앱의 현장 목록·선택·동기화 대상에서 뺐습니다. 엑셀·OneDrive 의 시트와 행은 지우거나 비우지 않습니다. 이 기기에 남은 예전 기록은 화면에서 숨기고 어디에도 보내지 않습니다(삭제로도 보내지 않음). 같은 `그 외` 열을 쓰는 다른 현장을 다시 쓸 때도 택지 드림 개소는 그대로 셉니다.

## 바로 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://127.0.0.1:4317` 을 엽니다. 휴대폰에서는 같은 주소의 배포본을 홈 화면에 추가하면 PWA로 설치됩니다.

```bash
npm test          # 포인트 번호, 개소, 합격 제외, 청구 계산, 실제 xlsx
npm run build     # dist/ 정적 파일
npm run preview   # 빌드 결과 미리보기
```

첫 화면은 **데모**입니다. 현장을 고르면 샘플 검사 기록이 히스토리에 나오고, 합격/불합격을 누르면 이 브라우저 안의 엑셀이 즉시 고쳐집니다. 엑셀 연동 탭에서 파일을 받을 수 있습니다(군포·마전 리스트는 OneDrive에서 한 번 받은 뒤). 네트워크가 없어도, 한 번 연 뒤에는 IndexedDB에 남습니다.

## 하루 작업 흐름

1. 현장(마지막 선택 기억), 검사일, 평일/공휴일, 검사자 둘, 근무 시작/종료.
2. 라인 번호. 현장별 최근 라인을 보여 줍니다. `HJ-M-002-350A`처럼 끝나면 관경을 `14" / 350A`와 스캔 길이로 표시합니다.
3. 큰 포인트 카드. 접두어 S / R / P / 직접 입력, 번호 +/−, 합격 / 불합격. 누르면 저장되고 같은 접두어의 다음 두 자리 번호로 넘어갑니다 (`S01` → `S02`). R로 바꾸면 그 라인의 다음 R(없으면 `R01`)입니다.
4. `R05-1`처럼 접미가 있으면 기준 번호는 5입니다. 저장 후 다음은 `R06`입니다. `R27-4-1`의 기준은 27입니다.
5. 범위 입력 `S05`~`S10`, 그중 불합격만 쉼표로.
6. 오늘 기록에서 실행취소, 합격/불합격 수정, 삭제.
7. 현장을 고르면 그 시트에 있던 이전 기록을 읽고, 라인의 마지막 기준 번호 + 1부터 이어 갑니다. 히스토리는 날짜별 합격/불합격 건수입니다.

불합격은 검사리스트에만 들어갑니다. 작업일지 개소와 거래명세서 금액에서는 빠집니다. 합격 포인트 하나 = 개소 하나. `S01`과 `R01`은 2개소입니다.

## OneDrive에 연결하기

설정(톱니)에서 **OneDrive**를 고르고 Microsoft 계정으로 로그인합니다. 개인 계정용입니다. 그다음 검사리스트, 작업일지, 거래명세서 파일을 OneDrive에서 고릅니다.

검사리스트는 두 파일입니다. 현장(시트)마다 자기 리스트 파일에만 씁니다.

| 리스트 파일 | 현장(시트) |
| --- | --- |
| `평택에너지(택지,브레인,합정주공) NDT 리스트.xlsx` (설정에서 고름) | 드림 합정주공, 드림 화양, 브레인대지 인입 (지성 브레인·택지 드림 시트는 앱에서 지움, 파일은 그대로) |
| `PAUT NDT 리스트(군포, 마전).xlsx` (드라이브 루트, 자동 연결) | 지성 군포 PA, 아전 군포 PA, 지성 마전 PA (`지성마전 RT` 시트는 쓰지 않음) |

군포·마전 리스트는 설정에서 따로 고르지 않아도 알려진 항목 ID로 연결하고, 그 ID로 못 찾으면 드라이브 루트에서 정확한 이름으로 찾습니다. OneDrive 모드로 처음 동기화할 때 한 번 받아 세 현장과 기존 행을 불러옵니다. 이 파일은 관경(L)이 값(`750A`)으로 적혀 있어 수식 대신 값을 쓰고(`군포산본 이원화 750A-1`은 `RIGHT(F,4)`가 `0A-1`이 됨), 순번(A)이 비어 있는 새 행에는 다음 번호를 씁니다. 작업일지 열은 지성 군포 / 아전 군포 / 지성 마전, 거래명세서는 `지성군포`(75,000원/M), `지성 마전`(65,000원/m) 시트입니다. 아전 군포는 거래명세서(지성, 드림)에 시트가 없어 명세서를 건너뜁니다.

저장할 때마다 네 파일을 **따로따로** 보냅니다(검사리스트 평택 → 검사리스트 군포·마전 → 작업일지 → 거래명세서). 보낼 기록이 있는 파일만 엽니다. 한 파일이 실패해도 나머지는 계속하고, 실패한 파일만 다시 보냅니다.

1. **검사리스트**: Microsoft Graph 통합 문서 API(세션)로 해당 현장 시트에 행을 씁니다. 관경 칸은 `=RIGHT(F행,4)` 수식(군포·마전 리스트는 값), Y열에 앱 ID. 같은 앱 ID(Y)가 이미 있으면 그 행을 고치므로 다시 보내도 행이 늘지 않습니다. 시트 이름 앞 공백(` 드림 합정주공`)은 무시하고 찾습니다. 파일 전체를 올리는 예전 대체 경로는 없앴습니다.
2. **작업일지**: 파일을 내려받아 메모리에서 기존 OOXML 도우미로 그날 행(병합·이어쓰기 행 포함)을 계산한 뒤, **바뀐 칸만** 통합 문서 API로 씁니다. 열은 4행 머리글로 찾습니다(실제 파일: 드림 합정주공 J/K, 검사자 P/Q, 근무시간 S/T). 같은 날짜 행이 있으면 그 행을 고치고, 새 날짜는 마지막 기록 아래 빈 행에만 씁니다.
3. **거래명세서**: 같은 방식으로 PAUT 줄만 칸 단위로 씁니다. 비고(I열) 등 엑셀 어디에도 `앱` 같은 표시를 쓰지 않습니다. 앱이 쓴 줄은 이 기기(IndexedDB `statementOwned`)에 기억한 날짜·관경·개수로 알아보고(옛 버전이 I열에 남긴 `앱`은 읽기만 하고 지우지 않음), 사람이 적은 줄은 건드리지 않습니다. 빈 줄이 모자라면 Graph `range/insert`로 합계 앞에 행을 넣고 SUM 범위를 늘립니다.
   - **새 달 시트(예: `드림합정26.11`)는 만들지 않습니다.** 사용자가 PC 엑셀에서 직접 만듭니다. 그 달 시트가 없으면 그 현장·달만 건너뛰고 기록은 대기로 두며, 동기화 창에 주황색으로 `11월 거래명세서 시트를 만들어주세요 (드림합정26.11)`이 보입니다(실패 아님, 달은 숫자, 괄호 안은 만들 시트 이름). 리스트·작업일지·다른 현장 명세서는 그대로 반영되고, 시트가 생기면 다음 동기화 때 대기 기록을 채웁니다. 파일 전체 업로드는 하지 않습니다.
4. **토큰·재시도**: 파일 단계마다 토큰을 새로 받습니다. 401이면 토큰을 강제로 새로 받아 다시 보내고, 잠김(409/423)·429·5xx·연결 끊김은 잠시 기다렸다 최대 4번 보냅니다. 동기화 중에는 로그인 화면으로 넘기지 않고, 로그인이 필요하면 그 단계를 실패로 남깁니다.
5. **상태·다시 시도**: 기록마다 파일별 상태(`steps`)가 IndexedDB에 남습니다. 실패하면 화면 위에 어느 파일이 왜 실패했는지(예: `작업일지 · 실패 — PC 엑셀 등에서 파일을 쓰는 중이라 잠겨 있습니다 (7건)`)와 **다시 시도** 버튼이 보입니다. 오프라인이면 대기 건수와 "연결되면 자동으로 보냅니다"가 보입니다. 앱을 다시 켜면 대기·실패를 이어 보냅니다.
6. **백필**: 앱을 켤 때와 다시 시도할 때, 이미 리스트에 들어간 앱 기록(최근 62일) 중 작업일지 그날 그 열이 비었거나 명세서에 그 날짜·관경 줄이 없는 것을 채웁니다. 이미 뭔가 적혀 있으면(사람이 적었을 수 있음) 덮어쓰지 않습니다. 다시 시도 때는 리스트 파일도 받아 Y열 앱 ID 행을 찾습니다.

PC Excel에서 같은 파일을 편집 중이면 잠김으로 실패할 수 있습니다. 그때는 PC에서 저장하고 닫은 뒤 **다시 시도**를 누르세요. 칸 단위로 쓰므로 PC에서 고친 다른 칸을 덮어쓰지 않습니다.

### Azure 앱 등록 (무료, 개인 Microsoft 계정)

클라이언트 암호는 만들지 않습니다. 브라우저 SPA는 PKCE만 사용합니다.

1. [Azure Portal](https://portal.azure.com)에 로그인합니다. 개인 계정으로 Entra ID(구 Azure AD) 테넌트가 없으면 포털이 무료 디렉터리를 만들게 합니다.
2. **Microsoft Entra ID** → **앱 등록** → **새 등록**.
3. 이름 예: `PAUT 현장`.
4. 지원되는 계정 종류: **개인 Microsoft 계정만**.
5. 리디렉션 URI 플랫폼: **SPA(단일 페이지 애플리케이션)**.
   - 개발: `http://127.0.0.1:4317` 와 `http://localhost:4317` 를 둘 다 넣습니다. 브라우저 주소와 글자 그대로 같아야 합니다.
   - 배포 후: `https://본인도메인` 을 같은 곳에 추가합니다.
6. 등록 후 **애플리케이션(클라이언트) ID**를 복사합니다.
7. **API 사용 권한** → **권한 추가** → **Microsoft Graph** → **위임된 권한** → `User.Read`, `Files.ReadWrite` → 추가.
   개인 계정은 관리자 동의 버튼이 없어도 로그인할 때 사용자가 동의합니다.
8. **인증**에서 플랫폼이 SPA인지 확인합니다. 클라이언트 암호, 인증서, implicit grant는 추가하지 않습니다.
9. ID를 넣는 곳 (둘 중 하나, 설정 화면 값이 우선):
   - 앱 설정 화면의 **Azure 클라이언트 ID**. 브라우저에만 저장됩니다. 다시 빌드하지 않아도 됩니다.
   - 빌드 시점 환경 변수. `.env.example`을 `.env`로 복사한 뒤 `VITE_AZURE_CLIENT_ID=` 에 넣고 `npm run build`.
10. 권한 기관은 기본이 개인 계정용 `https://login.microsoftonline.com/consumers` 입니다. 회사 계정까지 쓰려면 `.env`의 `VITE_AZURE_AUTHORITY`를 `https://login.microsoftonline.com/common` 으로 바꿉니다.

로그인은 휴대폰에서 팝업이 막히지 않도록 리디렉션 방식입니다.

## 배포

정적 호스팅이면 됩니다. 서버 코드는 없습니다.

```bash
npm run build
```

`dist/` 를 Netlify, Cloudflare Pages, GitHub Pages, Azure Static Web Apps 등에 올립니다.

- SPA이므로 모르는 경로는 `index.html`로 보내야 합니다.
- HTTPS가 필요합니다. MSAL은 http 중 `localhost` / `127.0.0.1`만 예외입니다.
- 배포한 출처(예: `https://paut.example.com`)를 Azure 앱의 SPA 리디렉션 URI에 추가합니다.
- 서비스 워커가 앱 껍데기와 샘플 xlsx를 캐시합니다. 샘플이 2MB가 넘어 캐시 한도를 8MB로 올려 두었습니다.

## 엑셀에 쓰는 방식

**검사리스트.** 시트 이름의 앞뒤 공백은 파일 그대로 유지하고, 화면에서는 공백을 뺀 현장 이름을 씁니다. 다음으로 라인 번호가 비어 있는 행에 검사일, 라인, 포인트, 합부, 재질, 앱 ID를 넣습니다. 관경은 `RIGHT` 수식입니다. 순번이 이미 채워져 있으면 그 값을 유지합니다.

**작업일지.** 날짜가 있는 행이 하루의 시작입니다. 바로 아래, 날짜와 순번이 없는 행은 관경이 여러 개일 때의 이어쓰기입니다. 순번만 있고 날짜가 없는 행은 아직 쓰지 않은 다음 날 칸입니다. 합격만, 매핑된 열의 관경/개소에 넣습니다. 다른 현장 열은 건드리지 않습니다. 열이 `그 외`이면 여러 현장이 한 열을 쓰므로 관경을 `150A(드림화양)`처럼 현장 이름을 붙여 구분합니다.

**거래명세서.** 시트 이름은 파일마다 다릅니다 (`드림합정26.10`, `지성브레인2611`, `지성군포 26.4`). 같은 접두어의 **가장 최근 시트**와 같은 표기(점, 월 자릿수, 공백)로 이번 달 시트를 찾습니다. 없으면 만들지 않고 `12월 거래명세서 시트를 만들어주세요 (드림합정26.12)`처럼 요청하며 대기합니다. 이름 끝이 `AM`인 시트는 단가가 달라서, 접두어에 AM이 없으면 건너뜁니다. PAUT 행만 그 달의 합격 집계로 다시 쓰고, RT 행은 둡니다. 수량 수식은 `개소 × 길이`, 금액은 `단가 × 수량`입니다. 합계의 부가세 10%와 `ROUNDDOWN(..., -3)` 천 원 절사는 시트에 원래 있는 식을 유지합니다. 데이터가 미리 비워 둔 행을 넘으면 합계 줄 앞에 행을 끼워 넣고 SUM 범위를 늘립니다.

길이 기본값(파일의 관경표):

| 관경 | m |
| --- | --- |
| 200A | 0.7 |
| 250A | 0.8 |
| 300A | 1.0 |
| 350A | 1.2 |
| 400A | 1.3 |
| 450A | 1.5 |
| 500A | 1.6 |
| 550A | 1.8 |
| 600A | 1.9 |
| 750A | 2.4 |

150A, 700A, 800A는 길이표에 없습니다. 설정에서 m를 넣기 전에는 금액에서 빠지고 화면에 표시됩니다.

기본 매핑(설정에서 바꿉니다):

| 현장 | 작업일지 열 | 명세서 접두어 | 단가 |
| --- | --- | --- | --- |

## 기술

Vite, React, TypeScript. 스타일은 승인된 프로토타입의 어두운 모바일 화면을 따릅니다. 엑셀은 65,536행까지 서식이 깔려 있어 통째로 다시 만들지 않고, 값이 있는 셀만 읽고 해당 칸의 스타일을 유지한 채 값만 바꿉니다. PWA 매니페스트와 서비스 워커가 포함됩니다. 참고 탭의 외경/스캔/스케줄은 현장 입력보다 부가 기능입니다.

## 아직 확인이 필요한 것

- 거래명세서 문서번호(`KOST-…-A06`)는 월 번호와 1:1이 아닙니다. 10월 시트도 A06인 경우가 있습니다. 새 달 시트는 사용자가 만들므로 앱은 문서번호를 건드리지 않습니다.
- 지성브레인 헤더에는 PAUT 단가가 없고 행에 73,000원이 있습니다. 드림화양 시트에서는 PAUT 단가를 찾지 못했습니다.
- 지성군포 헤더에 압입구간 90,000원/m가 있으나 일반 행은 75,000원입니다. 압입 여부는 자동으로 나누지 않습니다.
- 시트 이름 규칙이 달마다 바뀝니다 (`26.7` → `2610`). 새 이름은 가장 최근 시트의 표기를 따릅니다.
- `RIGHT(라인,4)`는 끝이 `350A`일 때 맞습니다. `300A IN`처럼 뒤에 글자가 더 있으면 수식 결과는 깨집니다. 개소와 금액은 라인에서 **마지막 `숫자A`**를 사용합니다.
- `지성 마전 26.5 AM`처럼 이름 끝이 AM인 시트는 단가가 다릅니다(예: 173,000). 접두어에 AM을 쓰지 않으면 무시합니다.
- 같은 날짜의 작업일지 열을 엑셀에서 손으로 적어 둔 값은, 앱이 그 날짜를 다시 저장할 때 검사리스트의 합격 개수로 덮어씁니다. 다른 현장 열은 유지합니다.
- 같은 날 같은 포인트를 다시 합격으로 저장하면 행이 하나 더 생기고 개소도 하나 더 잡힙니다. 재검사를 개소에서 빼야 하면 알려 주세요.
- 화양 리스트 일부 행은 합부 칸이 비어 있어 합격으로 세지 않습니다.
